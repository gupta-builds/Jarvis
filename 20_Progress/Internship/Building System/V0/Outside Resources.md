# Outside Resources
## Purpose and reading guide
This is the implementation reference for the outside-repository research completed for the 2026-11-21 weekend build. It maps the code we inspected to the existing internship-research-loop code, identifies the failure or opportunity, and states what to adapt and what still needs proof. The sequence and priorities in [[Weekend Build]] remain a separate plan. Findings here correct technical assumptions in that plan where noted; they do not silently change its approved decisions.
**Evidence labels**
- **Observed in code:** the named implementation has the described behavior. This does not prove a real posting was lost.
- **Reproduced:** the behavior was exercised with isolated synthetic inputs or temporary files. The example is not a claim about a real employer or incident.
- **Observed live:** the named public service returned the described result at the stated time; results can change.
- **Needs verification:** a plausible effect, source contract, real employer, deployment state, or scale not established by this research.
The local repository was inspected at `74a894d` on the local `dell-latitude/deadline-quota-and-reseed-fixes` branch. This commit is not contained in the locally known `origin/master`; the local file paths below describe that snapshot and should be rechecked against the branch being built. ## Current pipeline and non-negotiable boundaries
Our implementation is not an empty scanner. It already fetches sources in `ingestion/sources.py`, `ingestion/freehire.py` and `ingestion/interndock.py`; normalizes them in `ingestion/normalize.py`; filters and classifies them under `core/`; selects candidates and writes dossiers through `run_pipeline.py`; and rechecks some written dossiers in `recheck.py`.
The unattended path must remain zero-LLM. Eligibility defaults to pass on genuinely unknown data and rejects on affirmative negative evidence. The ordered fail-closed write gate remains required fields, source duplicate, cross-source duplicate, URL liveness, format compliance. A new regex, keyword, threshold or negative-signal rule needs a dated real-data example beside the code. These are repository contracts, not guarantees that every current branch already follows them.
A liveness result of unknown must not be called live or closed. The existing fail-closed write gate can still defer an unknown result: permissive eligibility and a fail-closed write decision answer different questions. Do not silently write an unverified URL simply to preserve recall.
Jarvis and the code repository are separate repositories. Their pushes are not an atomic transaction. Preserve manual consent and current live note standards for Program, Contact, Tracker and Applying changes; this reference does not authorize sending messages, submitting applications, altering the vault's templates, or deploying changes.
## Corrections to the earlier reports and Weekend Build
- Our `ingestion/normalize.py` and dossier frontmatter already carry `date_posted`, and `screen_report.py` sorts by it. The missing work is provenance, reliability and useful age presentation. Greenhouse currently puts `updated_at` into `date_posted`; an update date is not necessarily an original posting date.
- Our `ingestion/posting_page.py` already recognizes some explicit citizenship, U.S.-person, clearance, export-control and OPT/CPT exclusion phrases. Do not describe these checks as absent or replace them with a universal citizenship assumption.
- Our `recheck.py` already performs a daily source-based sweep for eight sources. ApplyGuy, Freehire and InternDock are not in its `FEEDS`. Freehire omission was deliberate because its observed closure information lagged; use actual employer/ATS evidence, not Freehire feed absence as proof of closure.
- career-ops [close-stale](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/docs/SCRIPTS.md) closes long-unanswered application tracker rows after a preview and confirmation; it is not a stale-dossier liveness sweep. Its closing-soon command reports deadlines, and detect-reposts identifies possible repeated listings.
- career-ops' [triage mode](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/modes/triage.md) is an agent instruction, not its zero-token scanner. Its separate [automation guide](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/docs/AUTOMATION.md) describes other workflow variants. Neither establishes a calibrated deterministic job-fit model.
- career-ops' Workday scanner uses POST to query public job listings. That is different from submitting an application. Do not say that every career-ops script never sends POST.
- `core/company_registry.py` already centralizes some company facts and `TIER_RANK`; ATS company dictionaries are still spread across source modules. A unified registry is an extension and migration, not a replacement for something that does not exist.
- A mandatory global intern/co-op title guard, generic seniority denylist, source allowlist, U.S. country parameter, or age cutoff can silently remove valid opportunities. The Weekend Build proposes these; their endpoint semantics and false negatives need real-data measurement before they become hard gates. Per-company positive title extras broaden matches but do not prevent global-negative false negatives.
- A personal `own_deadline` is not an employer closing date. An old own deadline means a review target has passed; it does not prove a posting is closed. Keep it distinct from `deadline_posted` and independently verified liveness before any archive move.
- The current `grade_resume.py` scores individual tagged resume bullets by keyword overlap with a JD. It is a useful, explainable input to a future manual or deterministic ordering, but it does not currently score whole jobs or predict outcomes. Keep it; do not represent its raw overlap as calibrated fit.
- On 2026-11-21, a read-only Freehire query with the existing company and intern filters and `limit=1` reported metadata totals of 40 for Google and 4 for Uber. These are aggregator counts at that time, not a count of active, eligible or unique jobs. They did not exceed our current 200-result page cap on that check; the absence of pagination is still a structural limit for larger boards.
## Build 1: preserve every candidate and make recovery real
### InternDock: acknowledge a guide only after its results are durable
**Observed in code:** `run_pipeline.py` saves a guide URL as seen immediately after its one fetch. Its listings live only in that run's memory. A quota shortfall, deferral, rejection or later failure can remove those candidates from future consideration because the guide will not be fetched again. `ingestion/interndock.py` returns the same empty list for a request failure and for a non-drop, and the caller marks either processed.
**Study:** [ai-job-search scrape_state.py](https://github.com/ai-job-search-dev/ai-job-search/blob/d2afe00bfc9b7be8ffc2ee41acc22570970b76d4/tools/scrape_state.py), [rank_state.py](https://github.com/ai-job-search-dev/ai-job-search/blob/d2afe00bfc9b7be8ffc2ee41acc22570970b76d4/tools/rank_state.py), and career-ops [scan history handling](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/scan.mjs).
**Implement in:** `ingestion/interndock.py`, `run_pipeline.py`, a narrowly scoped durable state or queue module, and their matching tests. Return distinct failed, fetched-but-unrecognized, confirmed non-drop and parsed outcomes. Persist raw or normalized candidates with guide provenance before acknowledging a successfully parsed guide. Make pending candidates available across future quota selections and retries; keep request failures retryable. Preserve the prior real guide and non-drop fixtures.
**Prove:** successful drop with more candidates than a run can write; exact quota shortfall; failed scrape followed by recovery; interruption after candidate persistence; partial downstream write; duplicate guide; safe replay and no repeated paid fetch after durable success.
### Reseed and recheck: align vault commits with the UID manifest
**Reproduced:** `reseed.py` writes `dossier_uids.json` under scratch state but merges only seen IDs, exclusions and OPT cache back. Seen IDs can persist without the new path-to-UID mappings. `recheck.py` skips a dossier without a manifest entry. The existing `tests/test_reseed.py` does not assert manifest merge-back.
**Reproduced:** `vault_writer/writer.py` changes the manifest in repository state before recheck pushes the vault. On simulated vault push failure, recheck still proceeds to commit the changed manifest with its log. The vault may retain the old path while the manifest points into Viewed.
**Implement in:** `reseed.py`, `recheck.py`, `vault_writer/writer.py`, `core/git_ops.py`, state/reconciliation utilities and tests. Stage an operation with old/new paths and UID, confirm the Jarvis push, then advance the durable manifest; retain enough information to reconcile when the vault push succeeds but the repository-state push fails. Merge successful reseed mappings without erasing existing entries. Atomic file replacement helps with local corruption but does not solve cross-repository atomicity.
**Prove:** failure before and after each push, retries, rebase conflict, existing moved file, concurrent modifications, UID/path collision, and an idempotent reconcile. Do not mutate the live vault to test a failure scenario.
### Other state and logging work
- `core/git_ops.py` stages all changes with `git add -A`, and only some failures are converted to `GitPushError`. Audit commit, add, rebase and no-op behavior, and stage only owned paths where appropriate. A generic retry cannot establish a successful push if the network fails after the remote accepted it; reconcile remote state before deciding.
- `run_pipeline.py` stores exclusion and cache state before its final Jarvis push. Determine which changes are safe independently and which must be committed with a corresponding operation.
- The OPT cache returns a cached excluded verdict without using its `checked` date to expire or revisit it. The inspected local cache had 76 excluded verdicts checked from 2026-07-26 through 2026-08-24. This establishes no incorrect verdict. Preserve exact matched evidence and source, add rule/version provenance, and design bounded reconsideration; expiry means re-evaluate, not automatically eligible.
- Debate-loss and write-gate failure counts advance when the candidate is seen in the relevant condition and do not necessarily reset on intervening absent runs. Name the policy accurately and decide whether permanent exclusions are appropriate for ranking losses or uncertain network failures. A lower priority is not evidence of ineligibility.
## Build 2: source completeness and liveness
### Separate empty, failed, partial and filtered results
**Observed in code:** `ingestion/sources.py` catches request failures for individual Greenhouse, Ashby and Lever boards and returns the other results as one plain list. AIJobs returns an empty list on a request exception. `recheck.py` sees the returned list as complete and can interpret missing IDs as closed.
The same fetchers pre-filter by title or employment type. A still-listed job whose title or type changes can disappear from the recheck input. The mass-move brake only limits larger sweeps; it does not prove a smaller move is correct.
**Study:** [career-ops board-truncation.mjs](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/lib/board-truncation.mjs), [scan.mjs](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/scan.mjs), [provider contract](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/providers/ADDING_A_PROVIDER.md), and [ai-job-search scraper health guidance](https://github.com/ai-job-search-dev/ai-job-search/blob/d2afe00bfc9b7be8ffc2ee41acc22570970b76d4/.claude/skills/job-scraper/SKILL.md).
**Implement in:** `ingestion/sources.py`, `ingestion/freehire.py`, `core/schema_drift.py`, `run_pipeline.py`, `recheck.py` and source/recheck tests. Introduce an explicit result carrying source, board, raw IDs or listings, completeness, errors and counts. Retain useful results from healthy boards for discovery. Recheck only an unfiltered, complete board or a trusted per-job endpoint; a failed or partial board is unknown.
**Measure:** boards attempted/complete/empty/partial/failed; raw jobs; internship candidates; term/location/relevance survivors; selected/deferred/rejected/written. `update_zero_match_streaks` currently ignores `fetch_count == 0`, but that count is after the ATS internship prefilter, so a broken prefilter or all-board failure can evade the alert.
**Preflight:** `core/schema_drift.py` checks one record or representative board and `check_all()` can halt the whole run for the optional InternDock sitemap before the separately fail-open discovery function runs. Validate the response actually consumed, distinguish malformed envelope from a valid empty list, and define which failed sources may degrade independently. Do not discard healthy boards or hide schema failures.
### Replace status-only liveness with provider-specific evidence
**Observed in code:** `vault_writer/validate.py` uses HEAD with redirects. Request exceptions and non-2xx/3xx responses fail the gate. `run_pipeline.py` groups repeated `url_liveness` failures and can permanently exclude a UID after three occurrences. A 403, 405, 429, timeout or 5xx is not automatically proof of closure; a 200 can be a closed-job or generic search page.
**Study:** [career-ops liveness-api.mjs](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/liveness-api.mjs) and [Workday liveness tests](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/tests/liveness-api-workday.test.mjs). Upstream treats Workday 403 with a particular S22 body as withdrawn, but other 403s as inconclusive; it explicitly does not treat every Lever API 404 as authoritative.
**Implement in:** a small Python liveness module called by `vault_writer/validate.py` and `recheck.py`, preserving the five-check order. Return active/closed/unknown plus provider, reason, timestamp and evidence. Prefer verified fixed-host ATS APIs and safe URL parsing; add provider-specific body rules only with observed examples. Unknown should be retried or surfaced, not permanently classified closed. Add bounded retries and `Retry-After` handling without making every fetch unbounded. Recheck ApplyGuy, Freehire and InternDock dossiers by their own employer URL where a trustworthy checker exists; do not use aggregator absence as a substitute.
**Prove:** 403 challenge versus documented closure, 404 authoritative versus inconclusive, HEAD 405, 429 and 5xx, redirect to search/index, closed page returning 200, timeout, malformed JSON, request retries, and no move on unknown.
### Untrusted network boundaries
**Observed in code:** the write gate sends HEAD requests to listing-provided URLs with redirects enabled. No resolved-address or redirect-target guard was found in that path. A compromised listing could therefore present an SSRF risk; exploitation was not tested.
**Study:** [career-ops provider IP guard](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/providers/_ip-guard.mjs), [HTTP transport](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/providers/_http.mjs), and provider host assertions.
**Implement in:** shared HTTP/liveness transport. Accept only intended schemes; block private, loopback, link-local and otherwise non-public destinations; validate every redirect and the address actually dialed, including IPv4, IPv6 and rebinding cases. Fixed public ATS endpoints are preferable when identity is verifiable. Respect source limits, retries and endpoint terms. Test against isolated local fakes, never by probing real metadata services.
## Build 3: URL identity, preservation and deduplication
### Preserve functional query parameters
**Reproduced:** `normalize_freehire()` strips the entire query string. A synthetic employer URL with `gh_jid=12345&utm_source=freehire` becomes the generic jobs page, losing the job ID. Our own `ingestion/posting_page.py` contains an employer URL rewrite that needs `gh_jid`.
**Study:** [career-ops url-key.mjs](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/url-key.mjs). It removes narrowly identified tracking parameters and preserves functional or unknown parameters.
**Implement in:** `ingestion/normalize.py`, `core/identity.py`, URL utilities and tests. Preserve the original usable application URL. Derive a separate conservative comparison key. Verify real source examples before deleting any parameter; a duplicate left visible is generally safer than merging different postings.
### Scope IDs to their actual namespace
**Reproduced:** `core/identity.py` returns `jobid:<id>` without ATS or tenant. Two synthetic Workday tenants with the same requisition-shaped ID collide; a synthetic lookalike hostname also matches the raw URL regex. This is a demonstrated collision condition, not proof of a real lost opportunity.
**Study:** [career-ops listing-fingerprint.md](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/docs/listing-fingerprint.md), [listing-fingerprint.mjs](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/listing-fingerprint.mjs) and [url-key.mjs](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/url-key.mjs).
**Implement in:** `core/identity.py`, `ingestion/normalize.py`, source adapters and `vault_writer/validate.py`. Prefer an authoritative provider + full board namespace + posting ID supplied by the source. Parse hostnames as hostnames, not substrings in arbitrary URLs. Treat incomplete identity or company/title similarity as uncertain rather than a conclusive merge. Keep verified aliases only when supported by evidence, including Workday public/private-site variants.
**Migration:** compare old and new keys on the existing manifest/dossiers in a read-only report; do not rewrite historical keys or merge notes automatically. Tests must retain the real Virtu, Google, Palantir, American Express and Workday duplicate examples while adding cross-company, cross-provider, lookalike-host and same-title/distinct-requisition cases.
## Build 4: filtering, content and useful screening
### Keep unknown evidence visible
**Observed:** `core/filter.py` contains positive-match gates that reject missing or unfamiliar terms, categories or degree labels in some sources, and free-text sources reject when neither a wanted term nor target year appears. A synthetic undated Greenhouse software internship was rejected. Bare Spring/Winter values are also explicitly rejected in existing tests despite ambiguity. Some behaviors reflect prior decisions and require review against the repository's stated permissive convention.
**Observed:** `core/relevance.py` applies title-shaped negative patterns to title plus description. A synthetic software internship mentioning a product management intern was rejected. `run_pipeline.py` can run stage 2 against an empty extracted body when the raw fetched page was nonempty.
**Study:** career-ops [employment-type normalizer](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/providers/_employment-type.mjs) leaves unrecognized labels unknown, and [title-keywords.mjs](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/title-keywords.mjs) provides configurable title matching. ai-job-search's [eligibility framework](https://github.com/ai-job-search-dev/ai-job-search/blob/d2afe00bfc9b7be8ffc2ee41acc22570970b76d4/.claude/skills/job-application-assistant/04-job-evaluation.md) distinguishes explicit evidence from silence.
**Implement in:** `core/filter.py`, `core/relevance.py`, `ingestion/posting_page.py`, `run_pipeline.py` and their tests. First replay real source examples and inspect rejects. Restrict title-specific rejection to trustworthy title evidence, treat missing or unusable body as unknown, and keep explicit negative signals traceable to their source. Classify citizenship/clearance requirements only when the wording and candidate context actually support it. A general statement that sponsorship exists is not conclusive proof of role-specific OPT acceptance.
**Do not copy:** an LLM prompt into the unattended run; a global positive title or exact seniority requirement as a silent hard gate; a generic claim that every clearance requirement has identical eligibility consequences; fabricated permit acceptance from silence.
### Screen and explain, not just score
**Existing:** `screen_report.py` provides a read-only per-bucket view ordered by preference and stored date. `grade_resume.py` ranks tagged bullets against one pasted JD by keyword overlap. The current comparator uses company preference then recency within buckets; its cross-bucket urgency stage is not exercised at the current per-bucket sort call sites.
**Study:** [career-ops triage.md](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/modes/triage.md), [coverage-check.mjs](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/coverage-check.mjs), and [ai-job-search rank.md](https://github.com/ai-job-search-dev/ai-job-search/blob/d2afe00bfc9b7be8ffc2ee41acc22570970b76d4/.claude/commands/rank.md).
**Implement in:** `screen_report.py`, `core/debate.py`, `grade_resume.py` only if needed, and associated tests. Show source, date provenance, posted age when actually known, stated deadline vs personal review deadline, liveness freshness, missing content and eligibility uncertainty. Retain company-tier grouping as defined by the user's decisions; career-ops' seniority tier is a different concept. If adding job-level ranking, show the individual evidence and missing fields; evaluate against a human-reviewed set before claiming it works.
**Date defect:** `_parse_iso_ts()` converts a date-only value using the host's local timezone. The same input produced different epoch values under UTC and America/Chicago in an isolated reproduction. Preserve date-only values or specify timezone explicitly. Never infer a posting date from discovery date.
**Content quality:** `extract_content()` may return empty or truncated content; its result must carry completeness before it is used to reject a job. Firecrawl failures currently produce thin dossiers without clearly recording the failure type. Preserve fail-open discovery while displaying the limitation.
### Duplicate and repost signals
[career-ops detect-reposts.mjs](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/detect-reposts.mjs) examines company/title history and multiple URLs. [ai-job-search scraper instructions](https://github.com/ai-job-search-dev/ai-job-search/blob/d2afe00bfc9b7be8ffc2ee41acc22570970b76d4/.claude/skills/job-scraper/SKILL.md) flag similar multi-location distributions and caution against accusing employers.
Use a source history or observation log before building this: record first/last seen, source, strong identity and observed changes. Flag possible repeats for review. A repeated title, multiple locations or old posting is not proof of fraud or closure, and two distinct requisitions must remain distinct.

## Build 6: GitHub Actions and operating the loop
**Observed:** `run.yml`, `recheck.yml`, and `reseed.yml` write to overlapping state/vault areas and do not declare a shared concurrency group. Git pull/rebase retry cannot by itself guarantee semantic consistency between independently computed JSON files or vault moves.
**Observed:** `file_github_issue()` and `disable_workflow()` ignore the subprocess return code. A simulated nonzero result returned normally. The hard-pause record and issue text can therefore claim a disable that was not confirmed.
**Observed during prior read-only GitHub queries:** workflows were reported active, while the latest returned discovery and recheck runs were dated 2026-08-29 and 2026-09-20 respectively. The cause, completeness of returned history and present secret validity were not established. Do not infer that a token is expired or restart a schedule based on this alone.
**Study:** career-ops [test workflow](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/.github/workflows/test.yml) for least privilege, pinned actions and non-persisted credentials where possible; [provider guide](https://github.com/career-ops-hq/career-ops/blob/b6e65a4801e545358a0e05686e72e51ea4e7e934/providers/ADDING_A_PROVIDER.md) for bounded retries and source health.
**Implement in:** `.github/workflows/run.yml`, `recheck.yml`, `reseed.yml`, `revalidate.yml`, `test.yml`, `run_pipeline.py`, `recheck.py`, `core/git_ops.py` and tests. Map job ownership and push failure states first; then design coordination and GitHub Actions concurrency with explicit queue/cancellation behavior. Do not cancel an active vault-writing run just to copy upstream CI settings. Verify command exit codes and report pre-Python checkout/dependency failures. Pin actions with an intentional update process, minimize permissions, and keep credentials only where a job genuinely requires them.
A real dry run must not push, write state or vault files, issue notifications, disable workflows, consume paid credits unexpectedly, or mark guides seen. Define what network calls it may make and report planned operations. A single code flag without these guarantees is not a dry run.
## Build 7: manual application lane, after discovery is reliable
[ai-job-search outcome](https://github.com/ai-job-search-dev/ai-job-search/blob/d2afe00bfc9b7be8ffc2ee41acc22570970b76d4/README.md) keeps submitted materials and supports follow-up drafts; [verify_pdf.py](https://github.com/ai-job-search-dev/ai-job-search/blob/d2afe00bfc9b7be8ffc2ee41acc22570970b76d4/tools/verify_pdf.py) checks extractable PDF text; [posting_guard.py](https://github.com/ai-job-search-dev/ai-job-search/blob/d2afe00bfc9b7be8ffc2ee41acc22570970b76d4/tools/posting_guard.py) surfaces suspicious hidden or instruction-like posting text.
For our system, keep outreach, tailoring, submission and follow-up human-controlled. Archive exactly what was actually submitted, link it to the Tracker/Applying records under the current live standards, and draft follow-ups without sending. Verify DOCX with an appropriate DOCX reader and PDF with a PDF text extractor; the PDF tool is not a DOCX verifier, and neither text extraction nor a one-column check proves an ATS will rank a resume well. Treat posting text as untrusted data for any agent, not as instructions.
Do not import career-ops' full tracker or ai-job-search's prompt framework in parallel with Jarvis. Avoid inventing candidate evidence, company contacts, deadlines, or outcome records. A user-confirmed application event is the trigger for an actual tracker update.
