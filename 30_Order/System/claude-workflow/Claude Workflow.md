# Claude Workflow
## Purpose
Local automation around Claude Code in the Jarvis vault: four hook scripts, the transcript exporter, and the scheduled jobs that commit the vault, back-fill missed sessions and run the weekly review. If it stops, sessions are not captured, writes are not guarded, PDFs can flood the context, and the git history and GitHub backup stop growing. The standing contract: Claude Code is the implementation surface, Claude Desktop is read-first planning, mobile is capture only, and MCP retrieves small context packs, not the whole vault.

## Failure Behavior
The write guard, the PDF guard and the continuity hook fail open: a parse problem exits 0, and an export error never blocks Claude Code from exiting. The internship guard reports a gap as context and never blocks. `git-auto-sync.ps1` exits 1 on a real problem (a pull-rebase conflict, a push that fails twice, a stale lock) and writes a final `=== git-auto-sync end (FAILED, ...) ===` line; it aborts a failed rebase instead of leaving the repo mid-rebase, and treats a lock older than 30 minutes as stale. The weekly review skips when its lock is under 120 minutes old. Each VBS launcher waits and returns the real exit code, so Task Scheduler's last result is honest. A failed sync is surfaced by the banner described in the sync-workflow record. Since 2026-11-05 `git-auto-sync.ps1` also (a) checks the whole vault for Windows reserved or unsafe file names (`nul`, `con`, `aux`, a trailing dot or space) before it touches git, logs each path, ends `FAILED, unsafe file name` and deletes nothing (`Get-UnsafeNames`, line 367; about one second); (b) caps its own log inside the run lock (`Invoke-LogCap`, line 393): past 1 MB the whole log moves to `git-auto-sync.log.1` (one previous generation) and the newest 2,000 lines stay, handled as bytes because older lines are in a legacy code page; and (c) catches any unexpected error, logs its script line and ends `FAILED, unexpected error` (line 545). Before that, an error in the hot-file check on a hidden tracked file (`.stignore`) ended a run with no end line and exit code 0.
