# Concept Workflow
Turn a reusable mechanism into one concept note that can be explained and applied without reopening the source.
## Use when
A topic is scheduled and its textbook note has landed (so the concept can be drafted before lecture), or after any lecture, lab, assessment, or mistake that exposes a mechanism.
## Steps
1. Read [[Concept Standard]] and search for an existing concept, alias, or heading before creating a file.
2. Build a source map: the textbook note, lecture or slides, code or notebook, and the lab, test, or assignment that touches it.
3. Create the note from [[Concept Template]]. Draft it before lecture and mark predicted emphasis and open questions instead of pretending the lecture happened.
4. Write the One-Line Answer, Mechanism, Contrast, Failure Modes, Evidence, and cards. Include code shape, notation, conditions, or test behavior where relevant.
5. Link the concept from the week, textbook, or assignment note, and link those notes back from Evidence.
6. After lecture or assessment, update the concept with the actual emphasis, corrections, and recurring mistakes, keeping source attribution.
7. Near an exam, deepen only in-scope concepts with worked reasoning and practice links, and add cards for recurring misses.
8. Run [[Vault Lint]] on the path and fix what it reports.
## Do not
Do not create duplicate concepts, use a textbook definition as the whole note, invent evidence links, or promote an inference to a fact. If two concepts blur, write the contrast as an open question and verify it.
## Done when
- A student can explain and apply the mechanism from the note alone.
- Sources, links, contrasts, failure modes, and cards are real and checked.
- Pre-lecture prediction and post-lecture evidence are distinguishable.
