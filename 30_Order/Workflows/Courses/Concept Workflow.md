# Concept Workflow
Use this when a scheduled topic, textbook section, lecture, code/PDF, lab, project, or repeated mistake reveals a reusable mechanism.
## Steps
1. Read [[Concept Standard]] and search for an existing concept, alias, or heading before creating a file.
2. Build a source map: textbook/NotebookLM output, lecture or slide/PDF source, code/notebook, lab/test/project, and relevant assignment or week.
3. Draft the concept before lecture when the textbook/source has landed. Mark predicted emphasis and unresolved questions rather than pretending the lecture already happened.
4. Write the one-line answer, mechanism, contrast, failure modes, evidence, and flashcards. Include code shape, notation, conditions, invariants, or test behavior where relevant.
5. Link the concept from the weekly/textbook/assignment note and link those notes back from Evidence.
6. After lecture or assessment, update the concept with actual emphasis, corrections, examples, and recurring mistakes. Preserve source attribution.
7. Near an exam, deepen only the in-scope concepts with worked reasoning and practice links, then add cards for recurring misses.
## Do not
Do not create duplicate concepts, use a textbook definition as the entire note, invent evidence links, or promote an inference to a fact. If the boundary between two concepts is unclear, write the contrast as an open question and verify it.
## Done when
- A student can explain and apply the mechanism from the note alone.
- Sources, links, contrasts, failure modes, and cards are real and checked.
- Pre-lecture prediction and post-lecture evidence are distinguishable.
